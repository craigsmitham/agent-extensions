# Software structure

Explanation and authoring guidance for C4 Software Systems, Containers,
Components, and selected structural views.

- [C4 model](c4-model.md) - How the C4 model uses hierarchical abstractions and selected diagrams to communicate software structure at different levels of detail, and where it needs complementary architecture views.
- [Documenting C4 software systems](documenting-c4-software-systems.md) - Use when a software-system boundary and value need C4 representation; create one Software System concept with clear responsibility and interaction context.
- [Documenting C4 containers](documenting-c4-containers.md) - Use when an application or data store inside a declared software system needs container-level identity; create one C4 Container concept with its responsibility and technology boundary.
- [Documenting C4 components](documenting-c4-components.md) - Use when a cohesive responsibility inside one C4 Container needs component-level identity; create one Component with a defined interface and exactly one owning container.
- [Documenting C4 views](documenting-c4-views.md) - Use when an audience needs a selected C4 perspective to answer one architectural question; create one View using consistent canonical elements and relationships.
