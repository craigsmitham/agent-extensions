# Evaluations

How Gen Stack uses criterion-bound assessment to produce evidence about a
realized system without allowing tests, observations, or results to become a
second authority for Requirements or assurance decisions.

- [Evaluation as bounded evidence](evaluation-as-bounded-evidence.md) - Why
  Evaluation is broader than testing but narrower than assurance, and how
  Definitions, Executions, Results, observations, and decisions retain
  distinct authority.
- [Designing a system evaluation approach](designing-a-system-evaluation-approach.md) - Use when establishing or revising how a system's evaluations are organized, traced, navigated, reported, and maintained across methods and repositories.
- [Designing evaluations for Surfaces](designing-evaluations-for-surfaces.md) - Use when Surface behavior or realization needs evaluation coverage; define subject- and Requirement-navigable evidence without turning interaction hierarchy into a runner taxonomy.
- [Designing evaluations for C4 structure](designing-evaluations-for-c4-structure.md) - Use when C4 Software Systems, Containers, or Components need satisfaction and realization evidence; evaluate canonical elements without treating Views as subjects.
