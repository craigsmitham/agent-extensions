# How to ship it

How does a change reach production safely and predictably?

The path a change travels from accepted work to released software, and the flow
and automation that keep that path honest. This section owns the movement of
change. How the system behaves once change has arrived belongs to
[How to run it](../operations/).

## Planned scope

| Area | Scope |
| --- | --- |
| Work management | Work-item taxonomy, content contracts, lifecycle, evidence, and tracker mapping |
| Flow | Batch size, branching, review gates, and release cadence |
| Build and release | Pipelines, artifacts, versioning, environments, and rollout strategy |
| Delivery automation | Workflow automation as it applies to integration and delivery |
