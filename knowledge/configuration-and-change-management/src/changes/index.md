# Changes


- [Authoring Changes](authoring-changes.md) — Use when a bounded proposed or authorized software modification needs consistent motivation, outcome, scope, constraints, completion, verification, risks, and next action.
- [Change template](change-template.md) — Provides a compact, tracker-neutral body fallback for a bounded Change without prescribing a delivery method or separate specification and design stages.
- [Classifying Changes](classifying-changes.md) — Use when a Change needs a truthful purpose classification without treating labels as diagnosis, priority, or authorization.
