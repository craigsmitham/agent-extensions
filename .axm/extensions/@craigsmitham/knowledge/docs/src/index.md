# Documentation craft knowledge

Portable concepts for documentation quality, oriented around Diátaxis.
Each topic has an **explainer** (`*-explainer`) and a **guide** (`*-guide`)
where both understanding and practice matter. Quality theory is explainer-
only. This bundle does not prescribe repository layout, metadata schemas, or
host tooling.

Skills such as `author-guide` and `review-docs` operate these definitions.

## Overall

* [Documentation craft](docs-explainer.md) - What effective documentation
  craft is: four jobs from user needs, map/compass, one job per document,
  host conventions win.
* [Documentation craft guide](docs-guide.md) - How to choose a type and
  produce a document with a clear primary job.
* [Documentation workflow](workflow-explainer.md) - Why craft improves through
  small iterative remediation: guide not plan, inside-out structure, complete
  not finished.
* [Documentation workflow guide](workflow-guide.md) - How to improve docs with
  choose → assess → one action → publish.
* [Documentation quality](quality-explainer.md) - Functional vs deep quality:
  type craft serves deep quality and can expose functional gaps.
